DOC — Comments and file header

MUSTEvery file opens with the standard headersvstyle · header · fix

Every `.sv` and `.svh` file begins with the copyright line, the all-rights-reserved line, and a `Description:` block that says what the file does.

The description is the only part of a file that survives being read out of context -- in a diff, a search result, or a model's context window. Copyright and licence state must be mechanical, not remembered, because a file that ships without it is a legal problem discovered late.

good
// Copyright (c) 2026 ACME Corp
// All rights reserved
//
// Description:
//   Synchronous FIFO with first-word-fall-through. Depth must be a power of
//   two. Full and empty are registered.
bad
// fifo.sv
module fifo #(

Sources: house style, lowRISC §Basic Template (shown as a template, not stated as a rule)

SHOULDThe header carries a real descriptionsvstyle · header_description

The `Description:` block says what the module does and names its non-obvious constraints; it is not the module name restated.

A description that repeats the identifier adds a line and no information. The constraints -- power-of-two depth, one-hot input assumption, latency -- are what a reader cannot recover from the port list.

good
// Description:
//   Gray-code pointer synchroniser. Source and destination clocks are
//   asynchronous; the pointer must change by at most one per source clock.
bad
// Description:
//   Gray counter module.

Sources: house style

MUSTEvery port carries a trailing commentsvstyle · port_comment · fix

Each port declaration ends with a `//` comment describing the signal.

The port list is the module's contract, and it is the one part of a module that other engineers and models read without opening the body. Direction and type are in the declaration; what the signal means, when it is valid and what it is relative to are not.

good
input  logic        clk_i,    // System clock
input  logic        rst_ni,   // Asynchronous reset, active-low
input  logic [7:0]  data_i,   // Payload byte, valid while valid_i is high
output logic        ready_o   // Sink can accept a byte this cycle
bad
input  logic        clk_i,
input  logic        rst_ni,
input  logic [7:0]  data_i,
output logic        ready_o

Sources: house style

MUSTEvery declaration carries a trailing commentsvstyle · decl_comment · fix

Each parameter, localparam, signal and net declaration statement ends with a `//` comment. Enumeration members are exempt.

A declaration is where a signal's purpose can be stated once instead of re-derived at every use. Enum members are exempt because their meaning belongs on the FSM case arm that acts on them, which is where lowRISC puts it -- commenting both places guarantees the two drift apart.

good
localparam int unsigned DepthW = $clog2(Depth);  // Bits needed to index the RAM
logic [DepthW-1:0] wptr_q, wptr_d;               // Write pointer, binary
bad
localparam int unsigned DepthW = $clog2(Depth);
logic [DepthW-1:0] wptr_q, wptr_d;

Sources: house style

MUSTEvery procedural block is introduced by a commentsvstyle · block_comment · fix

A one-line `//` comment sits on the line above every `always_ff`, `always_comb` and `always_latch` block, saying what the block computes.

Orientation without structure: the comment scrolls with the code and folds with it, so a reader skimming a collapsed module still sees what each block is for. Framed banner comments would do the same job but break native editor folding and rot when code moves.

good
// Advance the write pointer on an accepted write.
always_ff @(posedge clk_i or negedge rst_ni) begin
bad
always_ff @(posedge clk_i or negedge rst_ni) begin

Sources: house style

MUSTEvery instance is introduced by a commentsvstyle · instance_comment · fix

A one-line `//` comment sits on the line above every module instantiation, saying what the instance is for in this design.

The instance name says which module; the comment says why this design needs it. A reader tracing a signal through a hierarchy needs the second, and it is the thing the code cannot state.

good
// Two-flop synchroniser for the request from the slow domain.
prim_flop_2sync #(.Width(1)) u_req_sync (
bad
prim_flop_2sync #(.Width(1)) u_req_sync (

Sources: house style

MUSTComment placement follows the code it describesreview only

A comment on its own line describes the code that follows; a comment on a line with code describes that line. Use `//`, not `/* */`.

Quoting lowRISC: "A comment on its own line describes the code that follows. A comment on a line with code describes that line of code." Consistent placement is what lets a tool insert and a reader trust trailing comments at all.

good
// Hold the request until the far side acknowledges.
assign req_d = req_q & ~ack_i;  // Cleared by the synchronised ack
bad
assign req_d = req_q & ~ack_i;
// Hold the request until the far side acknowledges.

Sources: lowRISC §Comments

MUSTEvery FSM state arm is introduced by a commentreview only

Each state alternative inside an FSM case statement is preceded by a comment describing that state's function; those descriptions do not also live on the enum declaration.

Quoting lowRISC: "each state alternative should be preceded with a comment that describes the function of that state within the state machine". Keeping the description on the arm and not on the enum member means there is one copy to keep true.

good
// IDLE: wait for a request; nothing is in flight.
IDLE: begin
  if (req_i) state_d = BUSY;
end
bad
typedef enum logic [1:0] {
  IDLE,  // wait for a request
  BUSY   // transfer in flight
} state_e;

Sources: lowRISC §Finite State Machines

MUSTEvery deviation from this style is justified in a commentreview only

Code that deliberately departs from a rule in this guide carries a brief comment saying why, plus a lint waiver pragma where the tool supports one.

Quoting lowRISC: "It is always okay to deviate from the style guide by necessity, as long as that necessity is clearly justified by a brief comment". An unexplained deviation is indistinguishable from a mistake, so the next reader either breaks it or copies it.

good
wire tri_bus;  // Must be wire: connects to an inout port (style exception)
bad
wire tri_bus;

Sources: lowRISC §Style Guide Exceptions

SHOULDLong conditional blocks close with a matching labelverible lint · endif-comment mismatched-labels

A `` `endif`` far from its `` `ifdef`` carries a comment naming the condition it closes, and a named `begin` closes as `end : name`.

The opening condition has scrolled off screen by the time the reader reaches the close; without the label, matching them is a manual count. Verible checks both mechanically.

good
`ifdef SYNTHESIS
  // ...
`endif  // SYNTHESIS
bad
`ifdef SYNTHESIS
  // ...
`endif

STR — File structure

MUSTOne module per file, named after the moduleverible lint · module-filename package-filename one-module-per-file

A source file contains exactly one module, package or interface, and the file's basename is that design unit's name.

Every build system, waveform viewer and synthesis report addresses design units by name and finds them by filename. When the two disagree the mapping becomes a lookup only the author knows.

good
// fifo_sync.sv
module fifo_sync #(
bad
// fifo.sv
module fifo_sync #(

Sources: lowRISC §Files, Verilator DECLFILENAME

MUSTSystemVerilog files use `.sv`, headers use `.svh`review only

SystemVerilog source files are named `.sv`; files intended to be `` `include``d are named `.svh`.

The extension is how every tool decides whether to compile a file as a translation unit or treat it as text to be pulled into one. A header compiled standalone fails in ways that read as syntax errors far from the cause.

good
prim_assert.svh
bad
prim_assert.sv  // but only ever `include`d

Sources: lowRISC §Files

SHOULDDeclare signals close to their first usereview only

Signals, types, enums and localparams are declared close to where they are first used, grouped with the logic that drives them, rather than hoisted into a block at the top of the module.

Quoting lowRISC: "This makes it easier for the reader to find the declaration and see the signal type." Measured practice agrees -- 74.9% of OpenTitan declarations follow the first statement of the module. A hoisted block puts the type a screen away from every use.

good
// Write pointer, binary, wraps at Depth.
logic [PtrW-1:0] wptr_q, wptr_d;
always_ff @(posedge clk_i or negedge rst_ni) begin
bad
logic [PtrW-1:0] wptr_q, wptr_d;
logic [PtrW-1:0] rptr_q, rptr_d;
logic            full, empty;
// ... 200 lines ...

Sources: lowRISC §Declarations, OpenTitan practice (74.9% near-use)

MUSTPackages do not depend on each other cyclicallyreview only

Package dependencies form a directed acyclic graph; two packages never import each other.

SystemVerilog has no forward declaration for package contents, so a cycle has no legal compilation order. Tools that appear to accept one are relying on file order, which changes silently when the build system does.

good
package top_pkg;
  import common_pkg::*;  // common_pkg imports nothing from top_pkg
bad
package a_pkg; import b_pkg::*; endpackage
package b_pkg; import a_pkg::*; endpackage

Sources: lowRISC §Packages

SHOULDWildcard imports are local and justifiedreview only

`import pkg::*;` is used only for a package belonging to the same IP as the importing module, and the import sits in the module header rather than at file scope.

A file-scope wildcard import leaks every name in the package into every design unit in the file and into anything that includes it, so a later addition to the package can capture an identifier that already resolved elsewhere. Scoping it to the module bounds the damage to one unit.

good
module hmac_core
  import hmac_pkg::*;
#(
bad
import hmac_pkg::*;
module hmac_core #(

PRT — Ports and connections

MUSTPorts are declared in ANSI style, one per linesvstyle · ansi_ports

Module ports use the Verilog-2001 combined port-and-direction style, one port per line, with the closing `);` on its own line.

The non-ANSI style splits each port's direction, type and order across three places, so adding a port means three consistent edits and the compiler catches only some mistakes. One port per line is also what makes a trailing comment per port possible at all.

good
module fifo_sync #(
  parameter int unsigned Depth = 8  // Entries; must be a power of two
) (
  input  logic clk_i,   // System clock
  input  logic rst_ni   // Asynchronous reset, active-low
);
bad
module fifo_sync (clk, rst_n);
  input clk;
  input rst_n;

Sources: lowRISC §Module Declaration

MUSTClocks first, then resets, then the restreview only

The port list opens with the clock port(s), then all reset inputs, then the remaining ports grouped by interface.

A fixed prefix means the reader checks the clocking and reset scheme of an unfamiliar module by looking at one place, and an instantiation's first two lines are comparable across every module in the tree.

good
input  logic clk_i,    // System clock
input  logic rst_ni,   // Asynchronous reset, active-low
input  logic req_i,    // Transfer request
bad
input  logic req_i,    // Transfer request
input  logic clk_i,    // System clock
input  logic rst_ni,   // Asynchronous reset, active-low

Sources: lowRISC §Module Declaration

MUSTInstance ports are connected by name, never by position or `.*`svstyle · named_ports

Every instantiation connects ports by name. Positional connection and `.*` are not used in synthesizable RTL.

A positional list breaks silently when a port is inserted, and `.*` makes the connection depend on names matching in two files that no longer have to agree in writing -- a renamed signal connects to nothing and reports nothing. Measured practice agrees: `.*` appears in 28 OpenTitan files and every one of them is under dv/, fpv/, cov/ or sva/, never in synthesizable RTL.

good
fifo_sync u_fifo (
  .clk_i  (clk_i),
  .rst_ni (rst_ni),
  .data_i (data_i)
);
bad
fifo_sync u_fifo (.*);
fifo_sync u_fifo (clk_i, rst_ni, data_i);

Sources: lowRISC §Module Instantiation, BSG §prohibitions, OpenTitan practice (0 uses in RTL)

MUSTEvery port of an instance is connected explicitlyreview only

Every declared port appears in every instantiation, in declaration order; unused outputs are written as explicit no-connects and unused inputs are tied off explicitly.

An omitted port is indistinguishable from an oversight, and an unconnected input floats to `z` or a tool-dependent default rather than failing. Writing the tie-off states the intent where the next reader will look for it.

good
.status_o (),          // Unused: this instance never reports status
.debug_i  (1'b0),      // Tied off: debug hooks are not built in this config
bad
// status_o and debug_i simply absent from the instantiation

Sources: lowRISC §Module Instantiation

MUSTParameters are overridden by name, never by `defparam`verible lint · forbid-defparam module-port

Instance parameters are specified by name in the `#(...)` list. `defparam` is not used.

`defparam` applies from a distance, so the effective parameter value of an instance cannot be read from the instantiation; its elaboration order is also weakly specified and it is deprecated in IEEE 1800. Named overrides keep the value where the instance is.

good
fifo_sync #(
  .Depth (16)
) u_fifo (
bad
fifo_sync u_fifo ( ... );
defparam u_fifo.Depth = 16;

Sources: lowRISC §Module Instantiation, Verilator DEFPARAM

SHOULDInterfaces are not used as ports of reusable RTLreview only

Synthesizable, reusable modules take individual signals or packed structs as ports, not SystemVerilog interfaces.

Interface-typed ports have uneven synthesis support across Vivado, Quartus, Design Compiler, Genus and Yosys, and they hide the module's real fan-in and fan-out from lint and CDC tools. Measured practice is unanimous: zero interface-typed ports in synthesizable RTL across OpenTitan, Ibex and PULP.

good
input  tlul_pkg::tl_h2d_t tl_i,   // TileLink host-to-device, packed struct
output tlul_pkg::tl_d2h_t tl_o    // TileLink device-to-host
bad
tlul_if.device tl   // interface port in a reusable module

Sources: PULP practice, OpenTitan/Ibex/PULP measurement (0 uses)

SHOULDHandshake suffixes state the protocol contractreview only

A ready/valid interface names its backpressure signal for the protocol it implements: `_ready_and_o` when neither signal may depend combinationally on the other, `_ready_then_o` when valid may depend on ready, `_yumi_o` when the accept may depend on valid. A bare `_ready_o` does not say which.

The difference between these protocols is which signal is allowed to depend combinationally on which, and getting it wrong creates a combinational loop only at the point where two modules are finally connected -- often across a hierarchy boundary, long after both passed lint alone. The name is the only place the contract can live, because no linter can check it. Only `ready_and` and `credit` are safe at a top level where both ends are unknown.

good
output logic data_ready_and_o,  // r&v: must not depend on data_valid_i
input  logic data_valid_i       // r&v: must not depend on data_ready_and_o
bad
output logic data_ready_o   // Which protocol? The consumer cannot tell.

Sources: BSG SystemVerilog coding standard §handshakes, Taylor et al., DAC 2018

NAM — Naming

MUSTIdentifiers are lower_snake_caseverible lint · signal-name-style interface-name-style struct-union-name-style

Modules, packages, interfaces, instances, signals, ports, variables, functions, tasks and named blocks are named in `lower_snake_case`.

A single case convention means a reader never has to decide whether a difference in case is meaningful. The exceptions below -- parameters, constants, macros, types -- are deliberate: each marks a category of identifier whose binding time differs from a signal's.

good
logic [7:0] write_data_q;
bad
logic [7:0] writeData_q;

Sources: lowRISC §Naming Conventions

MUSTPorts carry a direction suffixverible lint · port-name-suffix

Module inputs end in `_i`, outputs in `_o`, and bidirectionals in `_io`.

Direction is declared once in the port list but read at every use inside the module and at every connection outside it. The suffix carries it to both places, so a signal driven in the wrong direction is visible where the mistake is written rather than where it is compiled.

good
input  logic       req_i,    // Transfer request
output logic [7:0] data_o    // Payload
bad
input  logic       req,
output logic [7:0] data

Sources: lowRISC §Suffixes

MUSTSuffixes stack in a fixed orderreview only

Multiple suffixes are concatenated without extra underscores, with `_n` first and `_i`/`_o`/`_io` last: `rst_ni`, `data_qi`, `valid_no`.

Without a fixed order the same signal is spelled `rst_in` in one module and `rst_ni` in the next, and the two no longer sort, grep or connect as the same name. Active-low-before-direction also keeps the direction as the true final token, which is what the linter's suffix regex anchors on.

good
input logic rst_ni,  // Asynchronous reset, active-low
bad
input logic rst_in,  // same signal, different spelling

Sources: lowRISC §Suffixes

MUSTFlop pairs are `_q` and `_d`verible lint · dff-name-style

A registered signal is named `<name>_q` and the value driving its input `<name>_d`; the two are declared together.

The pair makes a register visible as a register at every use, so reading a value one cycle late -- the most common RTL mistake -- becomes a spelling difference the reader can see rather than a timing property they have to reconstruct.

good
logic [7:0] count_q, count_d;  // Byte counter
always_comb count_d = count_q + 8'd1;
bad
logic [7:0] count, count_next;

Sources: lowRISC §Suffixes

MUSTType names end in `_e` or `_t`verible lint · enum-name-style typedef-enums typedef-structs-unions

Enumeration types are named `lower_snake_case_e`, other typedefs `lower_snake_case_t`, and every enum and struct used as a type is given a typedef name.

A declaration reads `state_e state_q;` -- type and variable are distinguishable without looking either up. Anonymous enums and structs cannot be named in a port list, a function signature or a package, so they force a copy of the definition at each use.

good
typedef enum logic [1:0] { IDLE, BUSY, DONE } state_e;  // Transfer states
state_e state_q, state_d;                               // Current/next state
bad
enum logic [1:0] { IDLE, BUSY, DONE } state_q, state_d;

Sources: lowRISC §Naming Conventions

SHOULDParameters are UpperCamelCase, true constants ALL_CAPSverible lint · parameter-name-style parameter-type-name-style

Tunable parameters and the localparams derived from them are named in `UpperCamelCase`; values that are immutable facts rather than tuning knobs are named in `ALL_CAPS`.

The case says whether overriding the value at instantiation is expected. Both spellings are accepted by the linter's CamelCase check, which matches lowRISC's own split rather than contradicting it. Measured practice: 99.8% UpperCamel across lowRISC code.

good
parameter  int unsigned Depth  = 8;             // Entries; override per instance
localparam int unsigned PtrW   = $clog2(Depth); // Derived, not tunable
localparam logic [7:0]  SOF_BYTE = 8'h7E;       // Protocol constant, immutable
bad
parameter int unsigned depth = 8;

Sources: lowRISC §Naming Conventions, lowRISC practice (99.8% UpperCamel)

SHOULDParameter names state the positive senseverible lint · positive-meaning-parameter-name

A boolean parameter is named for the condition being true (`EnableLogging`), not negated (`DisableLogging`).

A negated name turns every use into a double negative -- `if (!DisableLogging)` -- which is where sign mistakes hide. Defaults also read wrong: `DisableLogging = 0` requires two steps to mean "logging is on".

good
parameter bit EnableAssertions = 1;  // Compile the SVA blocks
bad
parameter bit DisableAssertions = 0;

Sources: Verible, house style

SHOULDMacros are ALL_CAPS and prefixed by their groupverible lint · macro-name-style macro-string-concatenation

`` `define`` macros are named in `ALL_CAPS`. A globally visible macro is prefixed with its group name and a double underscore; a file-local macro is prefixed with a single underscore and `` `undef``ed after use.

Macros ignore every scope in the language, so the name is the only namespace they have. Undefining a file-local macro keeps it from leaking into whatever file includes this one next, where a collision would silently take the wrong definition.

good
`define PRIM_ASSERT__VALID(x) ...
`define _local_helper(x) ...
`undef _local_helper
bad
`define VALID(x) ...

Sources: lowRISC §Naming Conventions

SHOULDNames describe purpose in whole wordsreview only

Signal names say what the signal is for, using whole words; signals that work together share a prefix, and a signal in a non-default clock domain is prefixed with that domain's identifier.

The clock-domain prefix is the load-bearing half: it makes a crossing visible at the point of assignment, so `assign vdata = udata;` reads as a bug on the line where it is written rather than at CDC-analysis time. Whole words matter because the reader of an abbreviation is usually not its author.

good
logic [7:0] uart_rx_data_q;   // uClk domain
logic [7:0] vsync_rx_data_q;  // vClk domain -- crossing is visible here
bad
logic [7:0] urxd_q;
logic [7:0] vrxd_q;

Sources: lowRISC §Use descriptive names, Cummings SNUG-2001 §clock domain naming

MUSTKeywords are never used as namesreview only

No identifier reuses a Verilog or SystemVerilog keyword, including keywords added after Verilog-2005.

SystemVerilog reserved many words that were legal Verilog-2001 identifiers, so a name that compiles today can break when a tool moves to a newer language level -- as a syntax error far from the declaration.

good
logic packet_type;
bad
logic type;  // `type` is a SystemVerilog keyword

Sources: lowRISC §Naming Conventions

FMT — Formatting and layout

MUSTThe formatter owns whitespaceverible lint · no-tabs no-trailing-spaces posix-eof line-length forbid-line-continuations

Indentation is two spaces, never tabs; lines carry no trailing whitespace; the file ends with exactly one newline; lines are at most 100 columns.

Bundled into one rule because none of them is a judgement call -- the formatter produces all four and a reviewer never has to discuss any of them. Two spaces and 100 columns follow the RISC-V open-source ecosystem this style descends from; 80 is too narrow once names carry direction and register suffixes.

good
always_comb begin
  data_d = data_i;
end
bad
always_comb begin
	data_d = data_i;   
end

Sources: lowRISC §Basics, Verible defaults

MUSTPort lists, parameters and named connections are tabularverible format

Port declarations, formal parameters, named port connections, named parameter overrides, module-level net declarations, struct members and enum assignments are aligned into columns. Loose assignment statements and case items are not.

These constructs are read as tables -- a reader scans one column to answer "what is the width of every port" -- and alignment is what makes the column exist. Loose assignments are excluded deliberately: aligning them makes every future edit rewrite its neighbours' whitespace, which is the cost that keeps Black from aligning anything. lowRISC requires alignment only for instantiation port expressions; the rest is ours, and costs nothing because the formatter does it.

good
input  logic        clk_i,    // System clock
input  logic [31:0] addr_i,   // Byte address
output logic        valid_o   // Response valid
bad
input logic clk_i, // System clock
input logic [31:0] addr_i, // Byte address
output logic valid_o // Response valid

Sources: lowRISC §Tabular Alignment, house style (the wider set)

MUST`begin` and `end` are always writtenverible lint · explicit-begin module-begin-block

Every `if`, `else`, `for`, `while` and `always` body is wrapped in `begin`/`end`, even a single statement. `begin` sits on the line of the construct that opens it and `end else begin` is written on one line.

A single-statement body that grows a second statement is a silent bug, and it is exactly the edit a model or a hurried human makes. This is stricter than lowRISC, which permits omitting `begin`/`end` when the whole statement fits on one line. Note the cost: neither the formatter nor the linter can insert `begin`/`end`, so on existing code every violation is a manual edit.

good
if (clear_i) begin
  count_d = '0;
end else begin
  count_d = count_q + 1'b1;
end
bad
if (clear_i) count_d = '0;
else count_d = count_q + 1'b1;

Sources: house style (stricter than lowRISC §begin/end)

MUSTNo stray or duplicated semicolonsverible lint · forbid-consecutive-null-statements suspicious-semicolon

There are no empty statements from consecutive semicolons, and no semicolon after the `end` of a block or after a module or generate body.

A stray semicolon after `if (cond);` silently makes the body empty and the following block unconditional -- it parses, simulates and synthesises, just not as written.

good
if (valid_i) begin
  data_d = data_i;
end
bad
if (valid_i);
begin
  data_d = data_i;
end

Sources: Verible

SHOULDMixed operators are parenthesisedverible lint · suggest-parentheses

An expression mixing operators of different precedence carries explicit parentheses around the intended grouping.

SystemVerilog's precedence table places the bitwise and comparison operators in an order that surprises most readers coming from C, and the failure is a wrong-but-plausible value rather than an error.

good
assign hit = (tag_q == tag_i) && (valid_q | force_i);
bad
assign hit = tag_q == tag_i && valid_q | force_i;

Sources: Verible

LNG — Language features

MUST`logic` everywhere; `wire` only for a real tri-statereview only

Signals are declared `logic`. `wire` appears only where a net is genuinely multiply driven, which in practice means a bidirectional pad, and carries a comment saying so.

`logic` is four-state like `reg` and `wire` but carries a single-driver check the compiler enforces, so an accidental second driver is an error at elaboration instead of a resolved value that simulates as `x` and synthesises as a short.

good
logic [7:0] data_q;  // Registered payload
bad
reg [7:0] data_q;

Sources: lowRISC §Use logic for synthesis

MUSTSequential logic is `always_ff` with nonblocking assignmentsverible lint · always-ff-non-blocking

Clocked logic is written in `always_ff` and assigns only with `<=`.

Cummings SNUG-2000 guideline #1. Blocking assignments in a clocked block execute in the active region of the stratified event queue, so a flop reading another flop assigned earlier in the same block sees the new value instead of the old one -- the simulation shows one pipeline stage where the synthesised gates have two, and which one you get depends on statement order.

good
always_ff @(posedge clk_i or negedge rst_ni) begin
  if (!rst_ni) begin
    b_q <= '0;
  end else begin
    b_q <= a_q;   // Reads the OLD a_q, as the hardware does
  end
end
bad
always_ff @(posedge clk_i) begin
  a_q = data_i;
  b_q = a_q;      // Reads the NEW a_q: one flop in sim, two in gates
end

Sources: Cummings SNUG-2000 guideline #1, lowRISC §Sequential Logic

MUSTCombinational logic is `always_comb` with blocking assignmentsverible lint · always-comb always-comb-blocking

Combinational logic is written in `always_comb` and assigns only with `=`. `always @(*)` and manual sensitivity lists are not used.

Cummings SNUG-2000 guideline #3, plus the sensitivity-list half: `always_comb` is checked by the tool for completeness and for having no blocking/nonblocking mix, where `always @(*)` is inferred and an incomplete manual list produces a latch in synthesis that simulation does not show. Nonblocking assignments inside a combinational block defer the update to the NBA region, so a value read later in the same block is stale.

good
always_comb begin
  sum = a_i + b_i;
  carry = sum[8];     // Sees the value just assigned
end
bad
always @(a_i) begin   // b_i missing: latch
  sum <= a_i + b_i;
end

Sources: Cummings SNUG-2000 guidelines #3, #10, lowRISC §Combinational Logic

MUSTBlocking and nonblocking assignments are never mixed in one blockverilator · BLKSEQ COMBDLY

A single `always` block uses either `=` or `<=` throughout, never both.

Cummings SNUG-2000 guideline #5. A mixed block splits its own updates across the active and NBA regions, so the behaviour depends on the order the two kinds of statement happen to appear in -- and is not what either kind alone would give.

good
always_ff @(posedge clk_i) begin
  a_q <= a_d;
  b_q <= b_d;
end
bad
always_ff @(posedge clk_i) begin
  temp = a_d;
  b_q <= temp;
end

Sources: Cummings SNUG-2000 guideline #5

MUSTA signal is driven from exactly one blockverilator · MULTIDRIVEN

Cummings SNUG-2000 guideline #6. Two blocks assigning one variable race: the simulator may execute them in either order within a time step, and synthesis resolves the conflict as a short or an arbitrary winner. The failure is order-dependent, so it often appears only after an unrelated edit.

  data_d = load_i ? data_i : data_q;

MUSTEvery `case` has a `default`verible lint · case-missing-default

Every `case`, `casez` and `unique case` statement has a `default` arm, even when it is empty or only raises an error.

Without a default, any unlisted value leaves the case's outputs unassigned, which infers a latch in combinational logic and leaves the state unchanged in sequential logic. `unique` does not substitute: it adds a runtime check in simulation but does not supply a value, and the check is absent in synthesis.

bad

  IDLE: state_d = req_i ? BUSY : IDLE;

endcase

MUSTLiterals state their widthverible lint · truncated-numeric-literal undersized-binary-literal numeric-format-string-style

Sized literals state a width that matches their context; a literal is never wider than its declared size, and `'0`/`'1`/`'x` are used for context-width fills.

An unsized literal is 32 bits wide, so comparing or assigning it silently zero-extends or truncates the other operand. Truncation of a constant is the case the compiler is least likely to warn about, because the value looks intentional.

MUST`casex` is not used; `casez` is used sparinglyreview only

Cummings SNUG-1999. `casex` treats `x` as a don't-care in the case *expression* as well as the items, so an input that is still unknown silently matches the first arm -- in his cited case an input unknown after reset release was masked in RTL simulation, gate-level simulation missed it, and the first ASIC came back flawed. `casez` has the same mechanism but only a floating `z` can trigger it, which is far less likely to mask a reset bug.

SYN — Synthesis and portability

MUST`full_case` and `parallel_case` are never usedreview only

No case statement carries a `full_case` or `parallel_case` synthesis directive.

Cummings SNUG-1999, "the evil twins". They live in comments, so the simulator ignores them while synthesis acts on them -- the design is described differently to the two tools by construction. `full_case` lets synthesis delete logic for values it now believes unreachable (his decoder loses its enable input entirely); `parallel_case` deletes a priority encoder that RTL simulation still models. They are most dangerous when they work, because nothing reports the divergence.

good
unique case (sel_i)
  2'b00: y_o = a_i;
  2'b01: y_o = b_i;
  default: y_o = '0;
endcase
bad
case (sel_i)  // synopsys full_case parallel_case
  2'b00: y_o = a_i;
  2'b01: y_o = b_i;
endcase

Sources: Cummings SNUG-1999 §full_case parallel_case

SHOULD`unique` and `priority` replace the directives, with carereview only

Use `unique case` with a `default` as the normal form. `priority case` states intentional overlap; plain `case` is used where neither claim holds.

Cummings SNUG-2005: these are real keywords, so simulation, synthesis and formal all read them, and they double as runtime assertions. But they are not a blanket substitute -- a `default` nullifies `priority` entirely (only `unique`'s overlap check survives), neither removes a latch caused by unassigned outputs, and both raise runtime errors against the standard default-assign-then-partial-case idiom.

good
unique case (state_q)
  IDLE: state_d = BUSY;
  BUSY: state_d = IDLE;
  default: state_d = IDLE;
endcase
bad
priority case (state_q)
  IDLE: state_d = BUSY;
  default: state_d = IDLE;   // `default` makes `priority` mean nothing here
endcase

Sources: Cummings SNUG-2005 §unique & priority

SHOULDPriority logic is written as if/else, parallel logic as casereview only

Intentional priority is written as an `if`/`else if` chain; a `case` statement is reserved for logic whose arms are genuinely mutually exclusive.

The construct states the designer's intent to every downstream tool and reader. A priority chain written as a case invites someone to add `parallel_case` later to "optimise" it, which is exactly the bug SYN-001 describes.

  resp_d = RESP_ERR;
end else if (valid_i) begin
  resp_d = RESP_OK;
end
bad

  err_i:   resp_d = RESP_ERR;   // Overlapping arms in a `case`
  valid_i: resp_d = RESP_OK;
endcase

Sources: Cummings SNUG-1999

MUSTModules are not instantiated recursivelyreview only

A module does not instantiate itself, directly or through a cycle.

Elaboration of a recursive hierarchy terminates only if the tool can prove the parameter sequence reaches the base case, and the tools disagree about which expressions they can prove. What elaborates in one synthesiser hangs in the next.

RST — Reset and clocking

MUSTResets are asynchronous and active-lowreview only

Flip-flops are reset asynchronously by an active-low reset named `rst_ni`, written as `always_ff @(posedge clk_i or negedge rst_ni)` with the reset test as the first `if` in the block.

This is the ecosystem's convention and measurement confirms it is followed, not just written: 902 of 959 reset `always_ff` blocks in OpenTitan and 108 of 130 in Ibex use async active-low, with exactly one positive-edge async reset in all of OpenTitan's hw/ip. Active-low matters physically -- a reset asserted by a pin being pulled low survives loss of the driver. Note that BSG argues the opposite (synchronous, high-true) precisely to avoid the de-assertion hazard RST-002 addresses; this style takes the async path and mandates the synchroniser instead.

good
always_ff @(posedge clk_i or negedge rst_ni) begin
  if (!rst_ni) begin
    count_q <= '0;
  end else begin
    count_q <= count_d;
  end
end
bad
always_ff @(posedge clk_i) begin
  if (rst) begin      // synchronous, active-high
    count_q <= '0;

Sources: lowRISC §Resets, Cummings SNUG-2003 §reset techniques, OpenTitan/Ibex measurement (94.1% / 83.1%)

MUSTEvery asynchronous reset passes through a reset synchroniserreview only

An asynchronous reset entering a clock domain is asserted asynchronously but de-asserted synchronously, through a two-flop reset synchroniser in that domain.

Cummings SNUG-2003, verbatim: "EVERY ASIC USING AN ASYNCHRONOUS RESET SHOULD INCLUDE A RESET SYNCHRONIZER CIRCUIT!!" Assertion is safe because it bypasses the clock path. Removal is the bug, two ways: de-asserting inside a flop's reset *recovery* window leaves it metastable, so the chip silently loses its reset state -- an intermittent field failure the controlled simulation never reproduces; and an asynchronous removal lets clock- and reset-tree skew release some flops a cycle before others, starting the design in a state nobody simulated. The synchroniser collapses this into one closed timing budget.

good
// Reset synchroniser: async assert, sync de-assert into clk_i.

  if (!rst_ext_ni) begin
    {rst_q, rst_meta_q} <= 2'b00;
  end else begin
    {rst_q, rst_meta_q} <= {rst_meta_q, 1'b1};
  end
end
bad
// External async reset driven straight into every flop in the domain.
always_ff @(posedge clk_i or negedge rst_ext_ni) begin

Sources: Cummings SNUG-2003 §reset synchronizer

MUSTEach clock domain has its own reset synchroniserreview only

In a multi-clock design, every clock domain instantiates its own reset synchroniser and its own reset distribution tree.

A reset de-asserted synchronously to one clock is asynchronous to every other, so sharing one synchroniser reintroduces exactly the recovery-window failure it was there to prevent -- in the domains nobody looked at.

SHOULDOnly control state is resetreview only

Reset the flops that must hold a known value at startup -- state machines, counters, valid bits, configuration -- and leave datapath registers unreset.

Every reset flop costs a reset-tree endpoint, routing and a larger cell, and the reset tree is one of the hardest nets to close timing on. A datapath register whose value is qualified by a valid bit does not need a defined value at startup, because nothing reads it until the valid bit says so.

good

    valid_q <= 1'b0;      // Control: reset
  end else begin

MUSTReset and clock nets are not mixedverilator · SYNCASYNCNET

A signal used as an asynchronous reset is not also used as ordinary data, and a clock is not gated with combinational logic; clock gating uses a dedicated integrated clock-gating cell.

FSM — State machines

MUSTState is a typed enum with `_q`/`_d`review only

FSM state is held in a variable of a `typedef enum` type, named `state_q` with next state `state_d`. State encodings are never `` `define`` macros.

Cummings SNUG-2003 §SystemVerilog FSM. A typed enum gives the tool a closed set of legal values, so an assignment of an out-of-range constant is an error and waveform viewers show state names instead of numbers. Macros have no type, no scope and no tool visibility.

SHOULDFSMs use the two- or three-block stylereview only

Cummings SNUG-2000 §FSM. Separating the register from the next-state logic means the reset, the clocking and the state transition each appear exactly once, and the combinational block can be read as a pure function of current state and inputs. A single-block FSM makes every output a registered output whether or not that was intended.

  state_d = state_q;
  ...
end

SHOULDFSM outputs crossing a module boundary are registeredreview only

Cummings SNUG-2000. A combinational output depends on the FSM's inputs in the same cycle, so it arrives late and its timing path continues into whatever the consumer does with it -- a path that neither module's timing constraints describe on its own.

CDC — Clock domain crossing

MUSTSingle-bit crossings go through a two-flop synchroniserreview only

Every one-bit signal crossing an asynchronous clock boundary passes through two flip-flops clocked by the destination clock, with no logic between them.

Cummings SNUG-2001. Across asynchronous domains a setup/hold violation on the first flop is a certainty, not a risk -- the phase relationship changes continuously. The second flop gives the first a full clock period for metastability to decay before anything samples it. Without it, a metastable output fans out and different gates resolve it differently, so the design disagrees with itself.

good
always_ff @(posedge dst_clk_i or negedge dst_rst_ni) begin
  if (!dst_rst_ni) begin
    {sync_q, meta_q} <= 2'b00;
  end else begin
    {sync_q, meta_q} <= {meta_q, src_signal_i};
  end
end
bad
always_ff @(posedge dst_clk_i) begin
  captured_q <= src_signal_i;   // One flop: metastability reaches the logic
end

Sources: Cummings SNUG-2001 §synchronizers

MUSTA multi-bit bus is never crossed bit by bitreview only

A multi-bit value is not crossed by putting a two-flop synchroniser on each bit.

Cummings SNUG-2001, and the most expensive mistake in this family because every bit is individually correct. Bit-to-bit skew from routing, rise/fall differences and across-die process variation cannot be matched away; a destination edge landing inside that skew window captures some bits this cycle and the rest next cycle, latching a word that never existed in the source. The same breaks paired controls -- a load and an enable arriving in different cycles means nothing loads.

good
// Gray-coded pointer: only one bit changes per increment, so a skewed
// capture yields either the old or the new value, never a third.
prim_fifo_async u_cdc_fifo ( ... );
bad
for (genvar i = 0; i < 8; i++) begin : gen_sync
  prim_flop_2sync u_sync (.d_i(data_i[i]), .q_o(data_sync[i]));
end

Sources: Cummings SNUG-2001 §multi-bit signals

MUSTMulti-bit crossings use a documented patternreview only

A multi-bit crossing uses one of: consolidation to a single bit regenerated locally; an unsynchronised data bus held stable behind a synchronised enable; Gray coding for counters; or an asynchronous FIFO.

Cummings SNUG-2001/2002, in his order of preference. Each pattern removes the skew problem a different way: consolidation leaves nothing multi-bit to skew; the held-stable formulation guarantees the bus is not changing while it is sampled; Gray coding guarantees at most one bit differs between consecutive values; the FIFO does the pointer crossing in Gray code and keeps the data in memory that is never crossed at all.

bad
// A free-running binary counter synchronised straight across.

MUSTSignals are registered before they crossreview only

A signal is registered in its source clock domain immediately before crossing; combinational logic does not drive a crossing directly.

Cummings SNUG-2001. Combinational output settles through a sequence of intermediate values, and every one of them is a potential edge for the destination to capture -- the crossing sees phantom pulses that never existed as logical values. Registering also improves MTBF by cutting how often the crossed signal changes.

MUSTOpen-loop pulses are wide enough to be capturedreview only

Cummings SNUG-2001. SHOULDModule outputs are checked for Xreview only

Module outputs carry an `` `ASSERT_KNOWN`` check, except outputs that may legitimately be unknown before first write, such as the read data of a FIFO or a memory.

X propagates silently through most RTL operators and is optimistically resolved by others, so an X originating in one module is often first noticed as wrong data several modules downstream. Checking at the boundary localises it to the module that produced it.

good
`ASSERT_KNOWN(ValidKnown_A, valid_o)
bad
// No X checks; an uninitialised counter shows up as wrong data three
// modules away.

MUSTLint runs clean before code is sharedreview only

`svstyle check` reports no MUST violations and `verilator --lint-only -Wall` reports no warnings before RTL is committed or handed over.

Every check in this guide is cheap at the point of writing and expensive later: a latch found by static timing analysis, a width truncation found in a chip bring-up lab, a missing case default found by a customer. The gate exists so that none of them travels.
