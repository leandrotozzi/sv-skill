§01

Quick start

Four steps from nothing to a module that passes lint, synthesis and its own testbench.

Install the skill

As a Claude Code plugin, from inside Claude Code:

claude code
/plugin marketplace add leandrotozzi/sv-skill
/plugin install systemverilog-rtl@sv-skill

Without the plugin system, copy or symlink skill/systemverilog-rtl into ~/.claude/skills/. The plugin also adds a hook that runs svstyle check --no-external after every .sv edit and tells Claude what it found. It never blocks.

Install the checker

The CLI the skill runs. Then the external tools, which are used when present.

shell
uv tool install svstyle        # or: pipx install svstyle
uvx svstyle check rtl/         # or run it once without installing

Verible v0.0-3946-g851d3ff4 or v0.0-4296-g0f262651 (tested versions) for formatting and lint, Verilator 5, and Yosys. The OSS CAD Suite ships Verilator, Yosys and the yosys-slang plugin in one download.

Configure the project (optional)

One .svstyle.toml at the repository root covers the tree.

.svstyle.toml
company = "ACME Corp"   # fills <Company> in every header
synth   = "yosys"       # or "yosys-slang"; checks synthesis on every run

Ask for hardware

No need to name the skill: any SystemVerilog request loads it.

§02

How the skill works

What Claude does between your prompt and the finished RTL. Each step exists because skipping it cost a round of check, edit, check in the evals.

  1. 01

    Read the rules

    references/rules.md: one line per rule, short on purpose. Then the synthesis subset for the configured tool, and the multi-clock guide if the design needs it.

    • synth-yosys.md when synth is yosys or unset
    • synth-yosys-slang.md for yosys-slang
    • multi-clock.md + rules-cdc.md with more than one clock or an asynchronous input
  2. 02

    Start from a template

    Never a blank file: each template in assets/ already passes svstyle check, so header, port order, reset style and comment layout come for free. Module and file are renamed together.

    • skeleton.sv: any module
    • fsm.sv + fsm_pkg.sv: a state machine
    • sync_ff.sv: a synchroniser
    • skeleton_tb.sv: the testbench
    • assert_macros.svh: `ASSERT, `ASSERT_KNOWN
  3. 03

    Write the comments as it goes

    The fixer can only insert // TODO: describe, which keeps the file passing and flags a gap. Real comments are written with the code: header description, every port and declaration, a line above every block and instance, every FSM arm.

    Widths match on every assignment, no keyword used as a name, no temporary with bits never read, no assertion the type already guarantees.
  4. 04

    svstyle fix

    Verible formats the file; svstyle inserts what is missing (header, `default_nettype none / `resetall, labels) and modernises legacy code only where the syntax tree proves the meaning is unchanged.

    reg/wire → logic, always @* → always_comb, always @(posedge) → always_ff, generate removed, functions made automatic.
  5. 05

    svstyle check --synth

    One report from four tools, every finding as file:line:col: RULE-ID message. [fix available] means fix handles it; the rest is the author's.

    Every file of the design in one call, so Verilator can elaborate the hierarchy. -I DIR for `includes elsewhere.
  6. 06

    Simulate

    A clean check means well formed, not correct. A self-checking Verilator testbench in tb/<name>_tb.sv compares the outputs, every cycle, against a model written from the spec, never from the RTL.

    Skipped for small blocks: one clock, no memory or protocol, simple arithmetic, no fairness or ordering promise, under ~40 lines of logic. On a FAIL: decide from the spec which side is wrong, fix, rerun once.
  7. 07

    Walk the judgement list

    About a third of the rules need judgement. Before calling it done the skill checks them against the code: reset scope, FSM shape, unique case + default, parameter checks, assertions, naming, structure.

    A genuine departure is waived where it happens, with the reason: // svstyle: waive RST-001 DSP blocks need a synchronous reset.

Done means

  • svstyle check --synth exits 0 on every file of the design. SHOULD findings may remain, each one a deliberate choice that is reported.
  • No // TODO: describe is left anywhere in the RTL.
  • The testbench printed PASS and no `ASSERT fired, or the block was small enough to skip it, and the skill says so.
  • The judgement list was walked; every departure carries a DOC-009 waiver with its reason.
  • The summary says what ran, what it reported, which SHOULDs stayed and why, and what the testbench covered (directed cases, random cycles, seed) and did not.

When the interface is given

A spec, a benchmark, vendor IP or existing code may fix the module name, port names or the reset style (clk, reset, a synchronous active-high reset). Then the skill keeps them exactly as given: the house style is for what it chooses, not for a contract it was handed. Everything inside still follows the style, and what the interface forces is waived with the reason, which doubles as the port comment.

a port list fixed by a spec
input  logic clk,    // svstyle: waive NAM-002 fixed interface; system clock
input  logic reset,  // svstyle: waive NAM-002 fixed interface; sync reset, active-high

Reviewing, or bringing legacy RTL into the style, follows existing-code.md: fix modernises only what it can prove unchanged, and --baseline lets CI fail only on new findings.

§03

The house style

lowRISC lineage: _i/_o, clk_i, rst_ni, _q/_d, CamelCase parameters, 100 columns; four-space indent is ours. Six ideas carry the rules.

DOC

Comments are part of the code

A header with a real description; a trailing comment on every port and declaration; a line above every block, instance and FSM arm. Checked and inserted by svstyle; no other open-source tool does it.

DOC-001DOC-003DOC-004DOC-005DOC-008
NAM

Names carry the hardware

Direction (_i/_o), register (_q/_d), polarity (_n) and type (_e/_t) are in the name, so a reader never scrolls up to a declaration.

NAM-001NAM-002NAM-003NAM-004NAM-006
LNG

One way to write each thing

logic everywhere; always_ff with <=, always_comb with = and a default for every output; every case has a default; literals state their width.

LNG-001LNG-002LNG-003LNG-006LNG-007
RST

Reset control, not data

Asynchronous active-low rst_ni, through a synchroniser per clock domain. State, counters and valids are reset; the datapath they qualify is not.

RST-001RST-002RST-004
FMT

The formatter owns whitespace

Four spaces, 100 columns, tabular port lists and connections: Verible's output, not anyone's taste. Nothing about layout is ever discussed in review.

FMT-001FMT-002FMT-003
SYN

Synthesis is the contract

Code in the subset the synthesis tool reads; no full_case, no combinational loops, no initial, no recursion. What simulates must be what is built.

SYN-001SYN-002SYN-005SYN-006

Severity

MUST · 59

A violation fails svstyle check (exit 1).

Reported, does not fail. Leaving one is a choice the author can explain.

Any finding, from any tool, is waived with one comment that names the rule and says why: // svstyle: waive DOC-004 <reason>. On its own line it covers the next line; trailing a line, that line. A waiver without a reason is ignored (DOC-009).

DOCComments and file header
MUSTAUTOFIX

Every file opens with the standard header

Every .sv and .svh file begins with the copyright line, the all-rights-reserved line, and a Description: block that says what the file does. A file that opens with the project's own licence header keeps it, followed by the Description: block.

enforced by svstyle · header

Why, and examples

The description is the only part of a file that survives being read out of context -- in a diff, a search result, or a model's context window. Copyright and licence state must be mechanical, not remembered, because a file that ships without it is a legal problem discovered late.

good
// Copyright (c) 2026 ACME Corp
// All rights reserved
//
// Description:
//   Synchronous FIFO with first-word-fall-through. Depth must be a power of
//   two. Full and empty are registered.
bad
// fifo.sv
module fifo #(

SHOULD

The header carries a real description

The Description: block says what the module does and names its non-obvious constraints; it is not the module name restated.

enforced by svstyle · header_description

Why, and examples

A description that repeats the identifier adds a line and no information. The constraints -- power-of-two depth, one-hot input assumption, latency -- are what a reader cannot recover from the port list.

good
// Description:
//   Gray-code pointer synchroniser. Source and destination clocks are
//   asynchronous; the pointer must change by at most one per source clock.
bad

//   Gray counter module.

MUSTAUTOFIX

Every port carries a trailing comment

Each port declaration ends with a // comment describing the signal.

enforced by svstyle · port_comment

Why, and examples

The port list is the module's contract, and it is the one part of a module that other engineers and models read without opening the body. Direction and type are in the declaration; what the signal means, when it is valid and what it is relative to are not.

good
input  logic        clk_i,    // System clock
input  logic        rst_ni,   // Asynchronous reset, active-low
input  logic [7:0]  data_i,   // Payload byte, valid while valid_i is high
output logic        ready_o   // Sink can accept a byte this cycle
bad
input  logic        clk_i,
input  logic        rst_ni,
input  logic [7:0]  data_i,
output logic        ready_o

Sources: house style

MUSTAUTOFIX

Every declaration carries a trailing comment

Each parameter, localparam, signal and net declaration statement ends with a // comment. A declaration spread over several lines, or one whose comment would not fit trailing within 100 columns, may carry it on the line directly above instead. Enumeration members are exempt.

enforced by svstyle · decl_comment

Why, and examples

A declaration is where a signal's purpose can be stated once instead of re-derived at every use. Enum members are exempt because their meaning belongs on the FSM case arm that acts on them, which is where lowRISC puts it -- commenting both places guarantees the two drift apart.

good
localparam int unsigned DepthW = $clog2(Depth);  // Bits needed to index the RAM
logic [DepthW-1:0] wptr_q, wptr_d;               // Write pointer, binary
bad
localparam int unsigned DepthW = $clog2(Depth);
logic [DepthW-1:0] wptr_q, wptr_d;

Sources: house style

MUSTAUTOFIX

Every procedural block is introduced by a comment

A one-line // comment sits on the line above every always_ff, always_comb and always_latch block, saying what the block computes.

enforced by svstyle · block_comment

Why, and examples

Orientation without structure: the comment scrolls with the code and folds with it, so a reader skimming a collapsed module still sees what each block is for. Framed banner comments would do the same job but break native editor folding and rot when code moves.

// Advance the write pointer on an accepted write.

bad

MUST

Comment placement follows the code it describes

A comment on its own line describes the code that follows; a comment on a line with code describes that line. Use //, not /* */.

enforced by review only

Why, and examples

Quoting lowRISC: "A comment on its own line describes the code that follows. A comment on a line with code describes that line of code." Consistent placement is what lets a tool insert and a reader trust trailing comments at all.

MUST

Every FSM state arm is introduced by a comment

Each state alternative inside an FSM case statement is preceded by a comment describing that state's function; those descriptions do not also live on the enum declaration.

enforced by review only

Quoting lowRISC: "each state alternative should be preceded with a comment that describes the function of that state within the state machine". Keeping the description on the arm and not on the enum member means there is one copy to keep true.

MUST

SystemVerilog files use .sv, headers use .svh

SystemVerilog source files are named .sv; files intended to be included are named .svh`.

enforced by svstyle · file_extension

Why, and examples

The extension is how every tool decides whether to compile a file as a translation unit or treat it as text to be pulled into one. A header compiled standalone fails in ways that read as syntax errors far from the cause.

SHOULD

Declare signals close to their first use

Signals, types, enums and localparams are declared close to where they are first used, grouped with the logic that drives them, rather than hoisted into a block at the top of the module.

enforced by review only

Why, and examples

Quoting lowRISC: "This makes it easier for the reader to find the declaration and see the signal type." Measured practice agrees -- 74.9% of OpenTitan declarations follow the first statement of the module. A hoisted block puts the type a screen away from every use.

bad
logic [PtrW-1:0] wptr_q, wptr_d;
logic [PtrW-1:0] rptr_q, rptr_d;

// ... 200 lines ...

MUST

Packages do not depend on each other cyclically

Package dependencies form a directed acyclic graph; two packages never import each other.

enforced by review only

Why, and examples

SystemVerilog has no forward declaration for package contents, so a cycle has no legal compilation order. Tools that appear to accept one are relying on file order, which changes silently when the build system does.

good
package top_pkg;
    import common_pkg::*;  // common_pkg imports nothing from top_pkg
bad
package a_pkg; import b_pkg::*; endpackage
package b_pkg; import a_pkg::*; endpackage

Sources: lowRISC §Packages

SHOULD

Wildcard imports are local and justified

import pkg::*; is used only for a package belonging to the same IP as the importing module, and the import sits in the module header rather than at file scope.

enforced by svstyle · import_scope

Why, and examples

A file-scope wildcard import leaks every name in the package into every design unit in the file and into anything that includes it, so a later addition to the package can capture an identifier that already resolved elsewhere. Scoping it to the module bounds the damage to one unit.

PRTPorts and connections
MUST

Ports are declared in ANSI style, one per line

Module ports use the Verilog-2001 combined port-and-direction style, one port per line, with the closing ); on its own line.

enforced by svstyle · ansi_ports

Why, and examples

The non-ANSI style splits each port's direction, type and order across three places, so adding a port means three consistent edits and the compiler catches only some mistakes. One port per line is also what makes a trailing comment per port possible at all.

    input  logic clk_i,   // System clock
    input  logic rst_ni   // Asynchronous reset, active-low
);

    input clk;
    input rst_n;

MUST

Clocks first, then resets, then the rest

The port list opens with a clock, then its resets, then the remaining ports grouped by interface. A module with several clocks repeats the pattern per domain: each clock opens its own group with its resets right after it.

enforced by svstyle · port_order

Why, and examples

A fixed prefix means the reader checks the clocking and reset scheme of an unfamiliar module by looking at one place, and an instantiation's first two lines are comparable across every module in the tree.

good
input  logic clk_i,    // System clock
input  logic rst_ni,   // Asynchronous reset, active-low
input  logic req_i,    // Transfer request
bad
input  logic req_i,    // Transfer request
input  logic clk_i,    // System clock
input  logic rst_ni,   // Asynchronous reset, active-low

Sources: lowRISC §Module Declaration

MUST

Instance ports are connected by name, never by position or .*

Every instantiation connects ports by name. Positional connection and .* are not used in synthesizable RTL.

enforced by svstyle · named_ports

Why, and examples

A positional list breaks silently when a port is inserted, and .* makes the connection depend on names matching in two files that no longer have to agree in writing -- a renamed signal connects to nothing and reports nothing. Measured practice agrees: .* appears in 28 OpenTitan files and every one of them is under dv/, fpv/, cov/ or sva/, never in synthesizable RTL.

good
fifo_sync u_fifo (
    .clk_i  (clk_i),
    .rst_ni (rst_ni),
    .data_i (data_i)
);
bad
fifo_sync u_fifo (.*);
fifo_sync u_fifo (clk_i, rst_ni, data_i);

MUST

Every declared port appears in every instantiation, in declaration order; unused outputs are written as explicit no-connects and unused inputs are tied off explicitly.

An omitted port is indistinguishable from an oversight, and an unconnected input floats to z or a tool-dependent default rather than failing. Writing the tie-off states the intent where the next reader will look for it.

MUST

Parameters are overridden by name, never by defparam

Instance parameters are specified by name in the #(...) list. defparam is not used.

enforced by verible lint · forbid-defparam — also verilator · DEFPARAM — also svstyle · named_params

Why, and examples

defparam applies from a distance, so the effective parameter value of an instance cannot be read from the instantiation; its elaboration order is also weakly specified and it is deprecated in IEEE 1800. Named overrides keep the value where the instance is.

    .Depth (16)
) u_fifo (

MUSTAUTOFIX

enforced by verible lint · always-ff-non-blocking — also svstyle · always_ff_style

Why, and examples

assign sum = base_i + offset_i;                    // base_i unsigned: all unsigned

Sources: IEEE 1800-2017 §11.8.1 (expression type rules), house style

SYNSynthesis and portability
MUST

full_case and parallel_case are never used

No case statement carries a full_case or parallel_case synthesis directive.

enforced by svstyle · synthesis_directives

Why, and examples

Cummings SNUG-1999, "the evil twins". They live in comments, so the simulator ignores them while synthesis acts on them -- the design is described differently to the two tools by construction. full_case lets synthesis delete logic for values it now believes unreachable (his decoder loses its enable input entirely); parallel_case deletes a priority encoder that RTL simulation still models. They are most dangerous when they work, because nothing reports the divergence.

good
unique case (sel_i)
    2'b00: y_o = a_i;
    2'b01: y_o = b_i;
    default: y_o = '0;
endcase
bad
case (sel_i)  // synopsys full_case parallel_case
    2'b00: y_o = a_i;
    2'b01: y_o = b_i;
endcase

Sources: Cummings SNUG-1999 §full_case parallel_case

SHOULD

unique and priority replace the directives, with care

Use unique case with a default as the normal form. priority case states intentional overlap; plain case is used where neither claim holds.

enforced by review only — also verilator · CASEOVERLAP

Why, and examples

Cummings SNUG-2005: these are real keywords, so simulation, synthesis and formal all read them, and they double as runtime assertions. But they are not a blanket substitute -- a default nullifies priority entirely (only unique's overlap check survives), neither removes a latch caused by unassigned outputs, and both raise runtime errors against the standard default-assign-then-partial-case idiom.

good
unique case (state_q)
    IDLE: state_d = BUSY;
    BUSY: state_d = IDLE;
    default: state_d = IDLE;
endcase
bad
priority case (state_q)
    IDLE: state_d = BUSY;
    default: state_d = IDLE;   // `default` makes `priority` mean nothing here
endcase

Sources: Cummings SNUG-2005 §unique & priority

SHOULD

Priority logic is written as if/else, parallel logic as case

Intentional priority is written as an if/else if chain; a case statement is reserved for logic whose arms are genuinely mutually exclusive.

enforced by review only

Why, and examples

The construct states the designer's intent to every downstream tool and reader. A priority chain written as a case invites someone to add parallel_case later to "optimise" it, which is exactly the bug SYN-001 describes.

good
if (err_i) begin
    resp_d = RESP_ERR;
end else if (valid_i) begin
    resp_d = RESP_OK;
end
bad
case (1'b1)
    err_i:   resp_d = RESP_ERR;   // Overlapping arms in a `case`
    valid_i: resp_d = RESP_OK;
endcase

Sources: Cummings SNUG-1999

MUST

Modules are not instantiated recursively

A module does not instantiate itself, directly or through a cycle.

enforced by review only

Why, and examples

Elaboration of a recursive hierarchy terminates only if the tool can prove the parameter sequence reaches the base case, and the tools disagree about which expressions they can prove. What elaborates in one synthesiser hangs in the next.

good
// Write the recursion as a generate-for over a flat array of stages.
bad
module tree #(parameter int N = 8) ();
    tree #(.N(N/2)) u_left ();

Sources: lowRISC §Generate Constructs

MUST

No combinational loops

No signal depends combinationally on itself: every feedback path passes through a flop.

enforced by yosys · logic-loop

Why, and examples

A combinational loop has no stable value to settle to, or several; it oscillates or latches depending on gate delays that neither simulation nor static timing analysis models. RTL simulation usually shows a plausible value or a delta-cycle limit, and the synthesis tool breaks the loop wherever it likes. The usual source is two always_comb blocks, or a ready/valid pair, that each read what the other drives.

good
assign ready_o = ~full_q;          // Depends only on a flop
bad
assign ready_o = valid_i & ~stall; // stall is computed from ready_o
assign stall   = ready_o & busy_i;

Sources: Yosys check, house style

SHOULD

No initial blocks in synthesizable RTL

Synthesizable RTL gives state its starting value through reset, not an initial block. Simulation-only code that needs one sits under ifndef SYNTHESIS, and elaboration-time checks go through ASSERT_INIT or a generate-time $error.

enforced by svstyle · initial_block

Why, and examples

ASIC synthesis ignores initial blocks, so a design that relies on one simulates from a value the silicon never has, and the first sign is a chip that does not come out of power-on the way the testbench did. FPGA flows do honour initial values for registers, which is why this is a SHOULD: a deliberate FPGA-only use carries a waiver saying so.

good
always_ff @(posedge clk_i or negedge rst_ni) begin
    if (!rst_ni) begin
        count_q <= '0;       // Starting value from reset
bad
initial count_q = '0;    // Ignored by ASIC synthesis

Sources: IEEE 1800-2017 §9.2.1 (initial procedures), house style

RSTReset and clocking
MUST

Resets are asynchronous and active-low

Flip-flops are reset asynchronously by an active-low reset named rst_ni, written as always_ff @(posedge clk_i or negedge rst_ni) with the reset test as the first if in the block.

enforced by svstyle · reset_style

Why, and examples

This is the ecosystem's convention and measurement confirms it is followed, not just written: 902 of 959 reset always_ff blocks in OpenTitan and 108 of 130 in Ibex use async active-low, with exactly one positive-edge async reset in all of OpenTitan's hw/ip. Active-low matters physically -- a reset asserted by a pin being pulled low survives loss of the driver. Note that BSG argues the opposite (synchronous, high-true) precisely to avoid the de-assertion hazard RST-002 addresses; this style takes the async path and mandates the synchroniser instead.

good
always_ff @(posedge clk_i or negedge rst_ni) begin
    if (!rst_ni) begin
        count_q <= '0;
    end else begin
        count_q <= count_d;
    end
end
bad
always_ff @(posedge clk_i) begin
    if (rst) begin      // synchronous, active-high
        count_q <= '0;

Sources: lowRISC §Resets, Cummings SNUG-2003 §reset techniques, OpenTitan/Ibex measurement (94.1% / 83.1%)

MUST

Every asynchronous reset passes through a reset synchroniser

An asynchronous reset entering a clock domain is asserted asynchronously but de-asserted synchronously, through a two-flop reset synchroniser in that domain.

enforced by review only

Why, and examples

Cummings SNUG-2003, verbatim: "EVERY ASIC USING AN ASYNCHRONOUS RESET SHOULD INCLUDE A RESET SYNCHRONIZER CIRCUIT!!" Assertion is safe because it bypasses the clock path. Removal is the bug, two ways: de-asserting inside a flop's reset *recovery* window leaves it metastable, so the chip silently loses its reset state -- an intermittent field failure the controlled simulation never reproduces; and an asynchronous removal lets clock- and reset-tree skew release some flops a cycle before others, starting the design in a state nobody simulated. The synchroniser collapses this into one closed timing budget.

good
// Reset synchroniser: async assert, sync de-assert into clk_i.
always_ff @(posedge clk_i or negedge rst_ext_ni) begin
    if (!rst_ext_ni) begin
        {rst_q, rst_meta_q} <= 2'b00;
    end else begin
        {rst_q, rst_meta_q} <= {rst_meta_q, 1'b1};
    end
end
bad
// External async reset driven straight into every flop in the domain.
always_ff @(posedge clk_i or negedge rst_ext_ni) begin

Sources: Cummings SNUG-2003 §reset synchronizer

MUST

Each clock domain has its own reset synchroniser

In a multi-clock design, every clock domain instantiates its own reset synchroniser and its own reset distribution tree.

enforced by review only

Why, and examples

A reset de-asserted synchronously to one clock is asynchronous to every other, so sharing one synchroniser reintroduces exactly the recovery-window failure it was there to prevent -- in the domains nobody looked at.

good
rst_sync u_rst_sync_sys  (.clk_i(sys_clk_i),  .rst_ni(rst_ext_ni), .rst_no(sys_rst_ni));
rst_sync u_rst_sync_usb  (.clk_i(usb_clk_i),  .rst_ni(rst_ext_ni), .rst_no(usb_rst_ni));
bad
// One synchroniser in the sys domain; usb flops use sys_rst_ni.

Sources: Cummings SNUG-2003

SHOULD

Only control state is reset

Reset the flops that must hold a known value at startup -- state machines, counters, valid bits, configuration -- and leave datapath registers unreset.

enforced by review only

Why, and examples

Every reset flop costs a reset-tree endpoint, routing and a larger cell, and the reset tree is one of the hardest nets to close timing on. A datapath register whose value is qualified by a valid bit does not need a defined value at startup, because nothing reads it until the valid bit says so.

good
always_ff @(posedge clk_i or negedge rst_ni) begin
    if (!rst_ni) begin
        valid_q <= 1'b0;      // Control: reset
    end else begin
        valid_q <= valid_d;
    end
end
always_ff @(posedge clk_i) begin
    data_q <= data_d;       // Datapath: qualified by valid_q, not reset
end
bad
// Every flop in a 512-bit datapath tied to the reset tree.

Sources: Xilinx UG949 §reset strategy, OpenTitan practice (57 unreset always_ff blocks)

MUST

Reset and clock nets are not mixed

A signal used as an asynchronous reset is not also used as ordinary data, and a clock is not gated with combinational logic; clock gating uses a dedicated integrated clock-gating cell.

enforced by verilator · SYNCASYNCNET

Why, and examples

A net that reaches both a reset pin and a data pin cannot be timed as either, and the synthesis tool picks one. A clock gated by if (en) in RTL produces glitches on the gated clock that the RTL simulation cannot show, because RTL has no notion of a glitch.

good
prim_clock_gating u_cg (
    .clk_i    (clk_i),
    .en_i     (enable_q),
    .clk_o    (clk_gated)
);
bad
assign clk_gated = clk_i & enable_q;   // Glitches on every enable change

Sources: Cummings SNUG-2001, Verilator SYNCASYNCNET

FSMState machines
MUST

State is a typed enum with _q/_d

FSM state is held in a variable of a typedef enum type, named state_q with next state state_d. State encodings are never `define macros.

enforced by review only

Why, and examples

Cummings SNUG-2003 §SystemVerilog FSM. A typed enum gives the tool a closed set of legal values, so an assignment of an out-of-range constant is an error and waveform viewers show state names instead of numbers. Macros have no type, no scope and no tool visibility.

good
typedef enum logic [1:0] { IDLE, BUSY, DONE } state_e;  // Transfer states
state_e state_q, state_d;                               // Current/next state
bad
`define IDLE 2'b00
logic [1:0] state;

Sources: Cummings SNUG-2003 §SystemVerilog FSM, lowRISC §Finite State Machines

SHOULD

FSMs use the two- or three-block style

An FSM is written as a sequential always_ff holding the state register plus a combinational always_comb computing next state and outputs; a third always_ff is added when outputs must be registered.

enforced by review only

Why, and examples

Cummings SNUG-2000 §FSM. Separating the register from the next-state logic means the reset, the clocking and the state transition each appear exactly once, and the combinational block can be read as a pure function of current state and inputs. A single-block FSM makes every output a registered output whether or not that was intended.

good
// State register.
always_ff @(posedge clk_i or negedge rst_ni) begin
    if (!rst_ni) begin
        state_q <= IDLE;
    end else begin
        state_q <= state_d;
    end
end

// Next-state and output logic.
always_comb begin
    state_d = state_q;
    ...
end
bad
always_ff @(posedge clk_i) begin
    case (state_q)
        IDLE: if (req_i) begin state_q <= BUSY; out_q <= 1'b1; end

Sources: Cummings SNUG-2000 §FSM coding styles

SHOULD

FSM outputs crossing a module boundary are registered

An FSM does not drive combinational (Mealy) outputs across a module boundary; such outputs are registered first, or the output logic moves into the consuming module.

enforced by review only

Why, and examples

Cummings SNUG-2000. A combinational output depends on the FSM's inputs in the same cycle, so it arrives late and its timing path continues into whatever the consumer does with it -- a path that neither module's timing constraints describe on its own.

good
always_ff @(posedge clk_i or negedge rst_ni) begin
    if (!rst_ni) begin
        grant_o <= 1'b0;
    end else begin
        grant_o <= (state_d == GRANTED);
    end
end
bad
assign grant_o = (state_q == IDLE) && req_i;   // Mealy, leaves the module

Sources: Cummings SNUG-2000 §FSM outputs

SHOULD

One FSM per module

A module contains at most one state machine.

enforced by review only

Why, and examples

Two FSMs in one module share a namespace and a reset block, so their states, transitions and outputs interleave in the source and neither can be read on its own. Splitting them also makes each one's interface -- and therefore its contract -- explicit.

good
// arbiter_fsm.sv and refill_fsm.sv, instantiated side by side.
bad
// One module holding state_q and mode_q, each a separate FSM.

Sources: Cummings SNUG-2000, lowRISC §Finite State Machines

CDCClock domain crossing
MUST

Single-bit crossings go through a two-flop synchroniser

Every one-bit signal crossing an asynchronous clock boundary passes through two flip-flops clocked by the destination clock, with no logic between them.

enforced by review only

Why, and examples

Cummings SNUG-2001. Across asynchronous domains a setup/hold violation on the first flop is a certainty, not a risk -- the phase relationship changes continuously. The second flop gives the first a full clock period for metastability to decay before anything samples it. Without it, a metastable output fans out and different gates resolve it differently, so the design disagrees with itself.

good
always_ff @(posedge dst_clk_i or negedge dst_rst_ni) begin
    if (!dst_rst_ni) begin
        {sync_q, meta_q} <= 2'b00;
    end else begin
        {sync_q, meta_q} <= {meta_q, src_signal_i};
    end
end
bad
always_ff @(posedge dst_clk_i) begin
    captured_q <= src_signal_i;   // One flop: metastability reaches the logic
end

Sources: Cummings SNUG-2001 §synchronizers

MUST

A multi-bit bus is never crossed bit by bit

A multi-bit value is not crossed by putting a two-flop synchroniser on each bit.

enforced by review only

Why, and examples

Cummings SNUG-2001, and the most expensive mistake in this family because every bit is individually correct. Bit-to-bit skew from routing, rise/fall differences and across-die process variation cannot be matched away; a destination edge landing inside that skew window captures some bits this cycle and the rest next cycle, latching a word that never existed in the source. The same breaks paired controls -- a load and an enable arriving in different cycles means nothing loads.

good
// Gray-coded pointer: only one bit changes per increment, so a skewed
// capture yields either the old or the new value, never a third.
prim_fifo_async u_cdc_fifo ( ... );
bad
for (genvar i = 0; i < 8; i++) begin : gen_sync
    prim_flop_2sync u_sync (.d_i(data_i[i]), .q_o(data_sync[i]));
end

Sources: Cummings SNUG-2001 §multi-bit signals

MUST

Multi-bit crossings use a documented pattern

A multi-bit crossing uses one of: consolidation to a single bit regenerated locally; an unsynchronised data bus held stable behind a synchronised enable; Gray coding for counters; or an asynchronous FIFO.

enforced by review only

Why, and examples

Cummings SNUG-2001/2002, in his order of preference. Each pattern removes the skew problem a different way: consolidation leaves nothing multi-bit to skew; the held-stable formulation guarantees the bus is not changing while it is sampled; Gray coding guarantees at most one bit differs between consecutive values; the FIFO does the pointer crossing in Gray code and keeps the data in memory that is never crossed at all.

good
// MCP: data held stable while a synchronised enable qualifies it.
assign data_stable_d = load_i ? data_i : data_stable_q;
prim_flop_2sync u_en_sync (.d_i(load_toggle_q), .q_o(load_toggle_sync));
bad
// A free-running binary counter synchronised straight across.

Sources: Cummings SNUG-2001, Cummings SNUG-2002 §async FIFO

MUST

Signals are registered before they cross

A signal is registered in its source clock domain immediately before crossing; combinational logic does not drive a crossing directly.

enforced by review only

Why, and examples

Cummings SNUG-2001. Combinational output settles through a sequence of intermediate values, and every one of them is a potential edge for the destination to capture -- the crossing sees phantom pulses that never existed as logical values. Registering also improves MTBF by cutting how often the crossed signal changes.

good
always_ff @(posedge src_clk_i) begin
    req_q <= req_valid && !busy;   // Registered, then crossed
end
bad
assign req_cross = req_valid && !busy;   // Glitches cross as real edges

Sources: Cummings SNUG-2001

MUST

Open-loop pulses are wide enough to be captured

A one-bit signal crossed open-loop through a two-flop synchroniser is held for more than 1.5 destination clock periods -- three destination edges. Narrower events use a closed-loop handshake.

enforced by review only

Why, and examples

Cummings SNUG-2001. A pulse shorter than the destination period can fall entirely between two destination edges and be missed, and one sampled near an edge may be captured by the first flop but not held long enough for the second. Three edges is the width that guarantees capture regardless of phase.

good
// Toggle: the level survives any number of destination periods.
assign req_toggle_d = req_i ? ~req_toggle_q : req_toggle_q;
bad
// A single source-clock-wide pulse crossing into a slower domain.

Sources: Cummings SNUG-2001

SHOULD

Crossings are confined to dedicated modules

Only the top level of a design sees more than one clock; every clock-domain crossing lives inside a module whose purpose is that crossing.

enforced by review only

Why, and examples

Cummings SNUG-2001. Confining crossings makes them findable -- the set of modules to review for CDC is a list rather than a search -- and it lets the rest of the design be verified, timed and lint-checked as single-clock logic.

good
// cdc_sync.sv, cdc_fifo.sv instantiated at the top; leaves are single-clock.
bad
// A leaf module taking both sys_clk_i and usb_clk_i.

Sources: Cummings SNUG-2001 §partitioning

GENGenerate and parameterisation
MUST

Every generate block is labelled

Every generate for body and every branch of a generate if carries a lower_snake_case label prefixed gen_, written as begin : gen_name.

enforced by verible lint · generate-label generate-label-prefix

Why, and examples

The label becomes part of the hierarchical path of everything inside it. Without one the tool invents a name like genblk3, so waveforms, timing reports, constraints and bug reports all address the logic by a number that shifts when an unrelated generate is added above it.

good
for (genvar i = 0; i < NumPorts; i++) begin : gen_port

    prim_fifo_sync u_fifo ( ... );
end

generate/endgenerate regions are not written, genvar is declared inline in the for header, and a generate body is not wrapped in an extra bare begin block.

generate

    end

MUST

Parameter legality is asserted, not assumed

A parameter with restricted legal values carries an assertion or an elaboration-time check stating the restriction.

enforced by review only

Why, and examples

A parameterised module is instantiated by people who did not read it. A power-of-two depth assumption that is violated produces wrong hardware rather than an error, and the failure appears as a functional bug in the instantiating design, far from the module that assumed it.

SHOULD

Assertions are written through the standard macros

SVA in RTL is written with the project's assertion macros (ASSERT, ASSERT_INIT, ASSERT_KNOWN) rather than bare assert property`.

enforced by review only

Why, and examples

The macros carry the clock and reset arguments, the severity, and the `ifdef guards that keep assertions out of synthesis. Bare assertions have to repeat all of that at every site, and the one that forgets the reset guard fires spuriously during reset in every simulation.

good
`ASSERT(ReqStableUntilAck_A, req_o && !ack_i |=> req_o, clk_i, !rst_ni)

Module outputs carry an `ASSERT_KNOWN check, except outputs that may legitimately be unknown before first write, such as the read data of a FIFO or a memory.

enforced by review only

X propagates silently through most RTL operators and is optimistically resolved by others, so an X originating in one module is often first noticed as wrong data several modules downstream. Checking at the boundary localises it to the module that produced it.

good
`ASSERT_KNOWN(ValidKnown_A, valid_o)

// No X checks; an uninitialised counter shows up as wrong data three
// modules away.

enforced by review only

Every check in this guide is cheap at the point of writing and expensive later: a latch found by static timing analysis, a width truncation found in a chip bring-up lab, a missing case default found by a customer. The gate exists so that none of them travels.

good

A directory stands for every *.sv below it. --select/--ignore take IDs or prefixes, ruff-style: --select DOC,PRT-003. --json gives machine-readable output; --no-external runs only svstyle's own checks.
