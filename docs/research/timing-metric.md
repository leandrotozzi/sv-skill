# Timing metric for `grade.py`

Research for the roadmap question "Timing quality: a cheap logic-depth
metric (Yosys `ltp` or `sta`) in `grade.py`". Measured 2026-10-15 with
Yosys 0.66 (local), on the 36 classics in `evals/files/classics/`.

## Summary

- No LLM-for-RTL benchmark uses a logic-depth count. The ones that score
  PPA use STA delay from OpenROAD/OpenSTA, OpenLane, Design Compiler or
  Vivado, with a PDK (NanGate45, SKY130, ASAP7). They report it as a
  ratio to the human reference, usually aggregated as a geomean.
- A PDK flow is too heavy for this repo. `ltp -noff` after
  `synth -flatten` is cheap: about 1 s per classic, 38 s for all 36. It
  needs no extra files, and it gave identical numbers on repeated runs and
  after renaming signals.
- It tracks ABC's own AIG level count. It also catches the style question
  that matters: an 8-way select written as an `if/else if` chain is 9
  levels deep, against 4 for `unique case` or AND-OR (1.37× the
  transistors).
- **Recommendation:** in `grade.py`, add one Yosys run,
  `synth -flatten -auto-top; ltp -noff; stat -tech cmos`. Record depth and
  transistor count as numbers, not pass/fail.
  - Compare `with_skill` against `without_skill` as per-eval ratios of
    medians, aggregated by geomean.
  - Flag a regression when the geomean depth ratio is above 1.10, or when
    a single eval is above 1.25.
  - Use the same Yosys binary for both sides. The frontend alone moves
    the numbers by up to about 6%.

Logic depth as a metric:

- I found no LLM-for-RTL paper that reports Yosys `ltp`, ABC
  `print_stats` levels or Yosys `sta`.
- VeriOpt feeds "logic levels" back to the LLM but reports STA results.
- The closest use of "gates on the longest path" is Basilisk
  ([2405.03523](https://arxiv.org/abs/2405.03523)), an SoC synthesis
  study that has nothing to do with LLMs.

Two rows were spot-checked against the arXiv pages. TuRTLe matches:
OpenLANE, SKY130A, 10 ns, and the 2 − min(ratio, 2) score. MCTS matches:
ADP, 31.8%. The 2601–2606 IDs came from a literature sweep and were not
re-opened individually.

## Yosys mechanics

The options below were read from `yosys -h <pass>` on 0.66 and from the
source at
[github.com/YosysHQ/yosys](https://github.com/YosysHQ/yosys).

### `ltp [-noff]`

Source: [`passes/cmds/ltp.cc`](https://github.com/YosysHQ/yosys/blob/main/passes/cmds/ltp.cc).

- It prints the longest topological path inside one module (help text:
  "the design must be flattened").
- Every cell adds 1, whatever its type. A `$_MUX_`, a `$_XOR_` and a
  `$_NOT_` each count as one level, and a word-level `$add` would also
  count as one. So it has to run on a gate netlist, after `synth`.
- `-noff` drops the FF and memory cell types registered by
  `setup_internals_mem()` and `setup_stdcells_mem()`. This makes the
  number the deepest register-to-register (or port-to-port) path.
- A combinational loop is cut, with a "Detected loop" warning.
- The gate set changes the number. `synth`'s own `abc` maps to
  `all,-NMUX,-AOI3,-OAI3,-AOI4,-OAI4` (`yosys -h abc`), so it counts
  ANDNOT, ORNOT and MUX as one level each.

### `sta`

Sources: [`passes/cmds/sta.cc`](https://github.com/YosysHQ/yosys/blob/main/passes/cmds/sta.cc)
and `kernel/timinginfo.h`.

- `sta` needs every cell to be a black-box or white-box module with
  timing arcs (`specify` data, read through `TimingInfo`).
- On a generic `synth` netlist, every `$_AND_`, `$_DFF_*` and similar cell
  gets "Cell type ... not recognised! Ignoring.", which makes the result
  useless.
- The following does run:
  ```
  synth_xilinx -flatten; read_verilog -lib -specify +/xilinx/cells_sim.v; sta
  ```
  On `rr_arbiter` it gives 5315, plus a "Critical-path does not terminate
  in a recognised endpoint" warning. That ties the number to one vendor's
  delay models. Not recommended.

### ABC levels

The `abc` pass runs only the combinational logic between FFs through ABC.

- `-script +cmd;cmd` replaces the default script. Commas become spaces.
- `print_stats` then logs `and = N lev = L`. On an AIG that is the
  technology-independent depth.
- Default scripts: `strash; &get -n; &fraig -x; &put; scorr; dc2;
  dretime; strash; &get -n; &dch -f; &nf {D}; &put`, and with `-fast`,
  `strash; dretime; map` (`yosys -h abc`).
- `-D <ps>` only sets a delay target for the mapper. It needs `-liberty`
  or `-constr` to mean picoseconds.
- Pitfalls:
  - AIG levels charge an XOR two levels, so the SECDED codecs show AIG lev
    19–20 against `ltp` 10–11.
  - The log format changes with width: `lev = 12` but `lev =153`, so parse
    with `lev =\s*(\d+)`.

### Area

- `stat -tech cmos` estimates a transistor count from the gate netlist,
  with no library. RTLScout uses it
  ([2606.06530](https://arxiv.org/abs/2606.06530)).
- `stat -liberty <lib>` gives µm², but needs a Liberty file. Yosys ships
  none, and none is on this machine.

### LUT depth

`synth -flatten; abc -lut 6; ltp -noff` counts `$lut` levels. It is too
coarse here: 1 to 3 levels for half the classics, so a one-level change
is a jump of 33–100%.

### General pitfalls

- **Flattening:** `ltp` and `sta` are per module. `grade.py` today runs
  `synth -auto-top` without `-flatten`, so a hierarchical output would
  report only its deepest single module.
- **Memories:** `synth` maps `$mem` to flops (`memory_map` in `synth -h`),
  so a FIFO's storage turns into a wide mux tree. `fwft_fifo` grows to
  45 966 AIG ANDs and takes 13 s.
- **Unmapped cells:** after `synth -noabc`, or with word-level cells left
  over, `ltp` counts an adder as 1. Always measure after full `synth`.
- **Versions and frontends:** the same file gives different numbers with
  `read_verilog -sv` and `read_slang` (measured below). Yosys and ABC
  releases change the mapping too. Compare only numbers from one binary
  in one run.

Results:

- **Determinism:** each command ran twice on every design, and all
  numbers were identical.
- **Renaming:** renaming every `*_q`/`*_d` signal in `fir`, `irq_ctrl`,
  `cordic`, `fp32_mul` and `csr_block` changed no number.
- **Runtime:** command A takes 38 s for all 36 designs, 25 s without
  `fwft_fifo`. C costs about 1.5× A.
- **Agreement:** `ltp` (A) and AIG lev (C) rank the designs almost the
  same. They diverge on XOR-heavy logic (`crc32`, `secded_*`, `cic_decim`)
  and on adders. On an AND/NOT-mapped `rr_arbiter`, `ltp` and ABC's mapped
  `lev` gave the same 21, which confirms that `ltp` counts gate levels.

The metric separates the case that matters: a priority chain where the
intent was parallel is 2.25× deeper and 1.37× bigger. The `_q/_d` split
costs one level (7%) on a small counter. That is about the size of the
noise that equivalent rewrites produce.

## Noise and normalisation in the literature

- **Reference.** Newer papers normalise to the benchmark's human
  reference: ChipSeek, VeriAgent, EvolVE, Alpha-RTL, REvolution.
  Optimisation papers normalise to plain Yosys output: RTLRewriter,
  SymRTLO, Metamorphosis.
- **Aggregation.** Geomean of per-design ratios (RTLRewriter, EvolVE,
  VeriAgent, PipeRTL, Alpha-RTL), arithmetic mean of % (SymRTLO,
  REvolution, ChipSeek), or win counts (RTLLM v1, COEVO).
- **Best-of-N** is common (SymRTLO, ChipSeek: best of 10). It hides
  sampling variance.
- **Noise** is almost never reported.
  - Alpha-RTL ([2606.05253](https://arxiv.org/abs/2606.05253)) re-ran the
    RTLLM2 references through its own flow and found median errors of 0.6%
    for area, 8.2% for delay and 31.3% for power. In a 4-seed replication,
    no metric reached p < 0.05.
  - RTLScout reports mean ± std over 3 repeats.
  - No paper states a minimum meaningful improvement. TuRTLe clips at 2×.
- **For this repo,** the tool itself is deterministic, so sampling is the
  noise: the model writes a different block each run. Equivalent rewrites
  moved depth by about 1 level or 5–7%, and so did the choice of frontend.

## Recommendation for `grade.py`

One extra Yosys call per graded output, reusing `read`:

```
{read}; synth -flatten -auto-top; ltp -noff; stat -tech cmos
```

- **Parse.** Read `Longest topological path in \S+ \(length=(\d+)\)` and
  `Estimated number of transistors:\s+(\d+)`. Record them in
  `grading.json` as numbers (`depth`, `transistors`), not as a pass/fail
  expectation, because there is no absolute right depth.
- **Report.** In `run.py`'s table, per eval, report
  `median(depth with_skill) / median(depth without_skill)` and the same
  for transistors, plus the geomean over evals.
  - For the classics, also report the ratio to the reference RTL, run
    through the same command, as TuRTLe and ChipSeek do.
  - Only score runs that pass functionally. A broken block is not
    shallow.
- **Regression threshold.** Flag when the geomean depth or transistor
  ratio is above 1.10, or when any single eval is above 1.25. That is
  more than 1.5× the ±7% noise measured above, and below TuRTLe's 2×
  floor.
- **Tools.** Run both sides with one Yosys binary in one run. Record the
  version (README "Tools" table).

Not doing:

- `sta` and `abc -D`: they need a cell library with timing.
- Liberty or PDK flows (OpenROAD, OpenLane): heavy, and they would pin
  this repo to a PDK.
- LUT depth: too coarse.
- AIG levels as the primary number: they over-charge XOR. Keep them as a
  cross-check if `ltp` ever looks odd.

Reproduce:

- Script: `depth.py` in this session's scratchpad (not committed).
- A one-liner for a single design:

  ```
  yosys -p "plugin -i slang; read_slang <files>; synth -flatten -top <T>; ltp -noff; stat -tech cmos"
  ```
